# 数学建模完整性、盲测与证据规范

本规范处理一种比“代码报错”更危险的失败：程序、结果和论文彼此一致，却回答了一个被悄悄改写的问题。任何阶段都不得用内部一致性代替题意正确性，也不得把历史题上的高分表现直接当成新题能力。

## 0. 防止把复盘写成过拟合补丁

本规范只固化跨赛题成立的不变量，不保存任何具体赛题的对象名称、标准答案、目标数值、获奖论文方法或题号触发规则。新增门禁前必须通过以下检查：

- **反事实检查**：把对象名称、单位和题型替换后，规则仍然成立；
- **跨题型检查**：至少在机理、优化、预测、评价/统计中的两个不同类别上有意义；仅适用于一种题型的规则必须标为可选适配器；
- **无答案检查**：测试只描述应检测的错误类型，不包含真实赛题的答案、近似目标值或可反推出答案的低熵散列；
- **最小约束检查**：门禁约束证据质量，不指定首选算法、固定图表数量或“高奖模型组合”；
- **反例检查**：既要有应拒绝的夹具，也要有使用不同方法但同样正确、应被接受的夹具。

复盘案例可以留在项目自己的审计报告中，但不能进入通用 skill、模板、测试断言或默认提示。若某条规则只能解释一个历史错误，应继续抽象或放弃固化。

## 1. 先声明任务模式

启动项目时必须在 `plan.md` 和 `reports/PROVENANCE.md` 中选择且只选择一种模式：

| 模式 | 适用场景 | 外部信息边界 | 可作出的能力声明 |
| --- | --- | --- | --- |
| `live-competition` | 正在进行且规则允许参赛的赛题 | 严格服从比赛规则；禁止搜索题目答案、已算结果或针对本题的解法 | 只能陈述本次工作的实际证据 |
| `isolated-benchmark` | 用历史题做隔离评测 | 从开始到封存均不得访问官方解答、优秀论文、讲评、答案摘要、旧工作区结果或目标数值 | 只能称“解答来源隔离”；不得声称模型参数从未见过该题 |
| `retrospective-audit` | 先独立求解，再与权威材料复盘 | 独立封存前同 `isolated-benchmark`；封存后才允许访问官方材料 | 必须分别报告独立结果和封存后修正，不能合并冒充一次命中 |
| `guided-study` | 明确借助范文、讲评或已知结果学习 | 可按用户授权访问，但必须逐项登记 | 不得用于评估独立解题能力 |

若任务模式在中途改变，必须先封存当前状态，在 `reports/DECISION_LOG.md` 记录变更时间、原因和影响，再继续。不得追溯性地把受指导结果改标为盲测结果。

### 人类监督模式

`live-competition` 默认且必须使用 `human-supervised`。Agent 可以准备审查材料、定位冲突和执行计算，但不能代表人类批准自己的工作。核心至少包含 intake、contract、model、results、paper、submission 六个检查点；启用正式文献检索阶段时再增加 literature 检查点：

1. `intake`：人类逐页/逐工作表确认题面、附件、单位、公式和勘误完整；
2. `literature`（启用时）：人类确认来源真实、允许访问、证据定位和候选路线比较，不把搜索摘要当原文；
3. `contract`：人类确认每项要求、固定量/可调量和重大歧义；
4. `model`：人类确认核心假设、基线、模型选择、验证计划和计算预算；
5. `results`：人类检查数量级、约束、敏感性、独立验证和异常结果；
6. `paper`：人类逐 ReqID 检查最终回答、图表、引用、结论强度和规则合规；
7. `submission`：人类查看最终 PDF 每页和提交表格，并亲自确认待提交文件。

每次批准必须记录 reviewer、时间、审查范围、查看的证据、结论和修改意见。Agent 不得生成虚构的人名、时间或 `APPROVED`；只能在用户明确确认后如实写入。人类要求修改时状态为 `CHANGES_REQUESTED`，下游 gate 不得继续。

模拟演习可以显式选择 `autonomous-simulation`。被跳过的人类检查标 `WAIVED_FOR_SIMULATION`；这不会使数值工作失败，但最终成熟度至多为 `UNVERIFIED`，不得称“比赛提交就绪”。为了让人类真正发现问题，每个检查点应生成短审查包：关键决策、正反证据、最高风险、可复核命令和需要明确回答的问题，而不是只请求“是否继续”。

### 分任务历史版本与反复决策

实际建模中，人类可能在解释、模型或表述之间多次往返。不得用覆盖文件或改写旧日志来“整理”这种纠结。使用内容寻址的分任务版本记录：

- `task_id` 可以是 ReqID、共享数据处理任务、模型模块、结果集、图表组或论文段落组；
- 每次快照保存显式文件清单、SHA-256、父版本、分支名、作者、时间、说明和依赖版本；相同内容去重；
- 多个候选分支可以并存。`select` 只改变当前选择并追加决策事件，永不删除旧版本；
- `human-supervised` 下选择最终分支必须引用明确的人类审查事件；Agent 可以创建候选，不能代替人类选择；
- `diff` 应展示文件和关键结构的变化；`materialize` 默认恢复到新目录，不覆盖当前工作树；
- `reports/CURRENT_VERSIONS.json` 的哈希必须被下游 gate 固定。改变任一被依赖任务的当前版本后，所有受影响阶段标为 `STALE`；
- 版本回退不是抹除后来历史，而是一次新的选择事件；必须记录为什么回退、哪些证据改变和哪些产物需要重跑。

版本历史解决可追溯和恢复，不证明候选本身正确。每个候选仍要通过相同题意合同、验证和人工审查门禁。

### 历史题污染声明

对于模型训练截止日前公开的赛题，即使当前会话没有浏览网页，也无法证明模型参数从未接触题目或答案。因此：

- 用“解答来源隔离”描述过程，不使用“真正未见题”“纯盲测”等不可验证表述；
- 把题面发布时间、当前模型/Agent 版本、允许访问的文件和工具写入来源记录；
- 评估泛化能力时，优先加入发布时间晚于模型知识边界的新题、私有题或程序化生成且人工验收的新题；
- 历史题成绩只能作为回归测试的一部分，不能单独估计新题获奖水平。

## 2. 隔离预检

在 `isolated-benchmark` 和 `retrospective-audit` 的独立阶段开始前：

1. 使用干净工作区，只放题面和原始附件；不要读取旧的 `code/`、`results/`、`paper/`、官方讲评或优秀论文。
2. 先列出文件清单和散列，再读取内容；将每个输入标为“题面”“原始附件”“规则文件”或“禁止材料”。
3. 若工作区已含旧答案或目标数值，不在原目录继续盲测。新建隔离工作区，只复制经确认的原始输入。
4. 把所有联网、搜索、人工提示、其他 Agent 输入和外部 API 调用登记到 `reports/PROVENANCE.md`。
5. 发现意外泄露后立即记录；受影响的结论降级为“污染后结果”，不得继续计作独立结果。

“没有主动搜索”不等于“没有信息泄露”。文件名、旧日志、论文摘要、测试断言和给定目标数值都可能泄露答案。

## 3. 题意合同（Problem Contract）

读取全部题面、规则和附件后，必须先建立 `reports/PROBLEM_CONTRACT.md`，再设计模型或写求解代码。合同至少包含：

### 3.1 题源与指纹

- 每个题面和原始附件的相对路径、文件类型、页数或维度、SHA-256；
- 题面版本、勘误和单位约定；
- 无法读取、损坏或疑似缺失的内容。

### 3.2 逐问需求表

每个响应单元拆成带唯一 ID 的原子要求，例如 `REQ-GROUP-N`。题面编号只用于分组；未编号的小问、命令式语句、附件填写和提交要求同样必须成为原子要求：

| 字段 | 内容 |
| --- | --- |
| 原文定位 | 页码、段落、表格或附件位置；必要时保留不超过理解所需的短语 |
| 要求动作 | 计算、预测、设计、证明、评价、比较或解释 |
| 必交输出 | 数值、单位、精度、时间点、表格、图、文件或方案 |
| 验收条件 | 什么证据足以说明真正回答了该要求 |
| 依赖关系 | 使用哪些前问结果，哪些条件只在本问新增 |

### 3.3 对象与自由度表

对每个关键量明确分类：

- 题面固定量：不得为了改善目标值而改变；
- 决策变量：题面明确允许调整；
- 状态变量：由模型和决策共同决定；
- 控制参数：算法设置，不是现实决策变量；
- 派生量：只能由已定义关系计算；
- 未知解释：在冻结前必须解决或显式保留为情景分支。

尤其要回答：边界和初始条件能否变化、定义域是否给定、调整某参数是否隐含改变另一个题面固定量。优化结果若来自扩大了自由度，就是另一个问题的答案。

### 3.4 歧义决策

每个会实质影响结果的歧义都必须有：候选解释、采用解释、排除理由、可证伪检查、对后续各问的影响。优先采用能同时解释全文、附件和新增条件的解释；不能靠“结果更好看”选择解释。

### 3.5 冻结门禁

合同只有满足以下条件才能标为 `FROZEN`：

- 全部原始材料已读并登记；
- 每问至少有一个 `REQ-*`；
- 固定量与可调量已分开；
- 必交文件、单位、精度和定义域已写明；
- 没有未处理的复选框、占位符或高影响歧义；
- 至少完成一次独立题意审查。

冻结后修改合同，必须在 `reports/DECISION_LOG.md` 追加记录，并列出被作废的模型、代码、结果、图表和论文段落。不能静默改写假设后只重跑有利部分。

## 4. 两条互相独立的验证链

### 4.1 语义验证链

逐条检查：

1. 结论引用了哪些 `REQ-*`？
2. 实现中的可变参数是否恰好等于合同中的决策变量？
3. 是否改变了固定端点、边界、初值、时间范围、单位或题面给定关系？
4. 输出的对象、时刻、精度和文件格式是否与要求一致？
5. 若删掉模型术语，结论是否仍直接回答题面动词？

如果第 2 或第 3 项不通过，即使数值与某篇论文相同，也必须判为语义失败。

### 4.2 数值验证链

逐项采用适用的证据：

- 量纲、单位和数量级检查；
- 守恒式、几何关系和所有约束残差；
- 极限情形、对称情形、可手算小样例；
- 步长、网格、容差、样本量或随机种子的收敛分析；
- 与独立公式、独立实现或另一求解器交叉验证；
- 灵敏度、不确定性和误差传播；
- 搜索域覆盖和所有候选极值的复核。

同一份代码导出的 Excel、JSON 和论文数值相等，只证明流水线一致，不是独立验证。

## 5. 优化、搜索与“全局最优”

- 搜索区间必须由题面、可行性条件、解析界或事件终止条件推出，不得使用未解释的“足够大”常数。
- 先证明或数值验证可行域覆盖，再比较目标值；不得只从单一起点运行局部优化器。
- 对一维或低维问题，枚举全部驻点、边界点和离散事件；对高维问题，说明全局性证据的强弱。
- 至少报告一次分辨率/容差收敛，并保存原始表格。
- 只有解析证明、严格界、穷举证书或有明确最优性保证的算法达到条件时，才称“全局最优”。否则使用“搜索到的最优可行解”“多起点范围内最优”或“启发式较优解”。
- 若目标对题面允许调整的参数理论上不变，应如实报告“不随该参数变化”，而不是擅自开放额外自由度制造改进。

## 6. 结论—证据账本

`results/claim_ledger.json` 是论文前的机器可检验账本。每条重要结论必须包含：

- 唯一 `id`、对应 `contract_refs`、结论文本和结论类型；
- 认知等级：`exact`、`proved`、`numerically_verified`、`approximate`、`heuristic` 或 `unverified`；
- 状态：`supported`、`provisional` 或 `rejected`；
- 数值结论的值、单位和报告精度；
- 至少一个结果证据路径和一个验证记录；
- 若写入论文，记录内部章节定位；这些内部 ID 不必出现在最终正文。

强度不得超过证据：局部搜索不能登记为已证明全局最优，拟合优度不能登记为因果关系，单一数据划分不能登记为稳定泛化。

## 7. 多 Agent 的最小泄露协议

Agent 的价值在于独立性，而不是把同一结论复述多次。优先分配以下角色：

1. **题意审查者**：只接收原始题面和附件，独立抽取要求、固定量和可调量；不接收主解合同、代码或目标数值。
2. **替代建模者**：接收冻结合同和原始数据，不接收主解数值；提出独立公式、边界和可证伪测试。
3. **数值审计者**：接收合同、代码和原始输入，不接收期望答案；复跑并寻找反例、收敛问题和魔法常数。
4. **论文审计者**：接收合同、账本、论文和图表；逐条查题意覆盖、假设漂移和结论强度。
5. **官方材料比对者**：只在允许的封存后阶段启用；单独记录差异，不能替主解回填历史。

审查者应返回“发现 + 证据位置 + 严重级别 + 建议测试”，不能只给笼统评价。若资源有限，题意审查优先于润色和绘图。

## 8. 封存、复盘与官方材料比对

独立阶段结束时：

1. 冻结题意合同、代码、结果、账本、论文草稿和运行日志；
2. 生成 `results/run_manifest.json`，记录相对路径、角色、大小和 SHA-256；
3. 在 `reports/PROVENANCE.md` 写入封存时间和清单哈希；
4. 此后任何修改都作为新版本，不覆盖独立版本。

允许查阅官方材料后，建立差异表：

| 结论/步骤 | 独立封存结果 | 外部材料 | 差异类型 | 根因 | 修正后状态 |
| --- | --- | --- | --- | --- | --- |

差异至少分为：题意解释、模型结构、数学推导、数值实现、输出格式、论文表达。官方材料也可能不完整或仅是示例思路；比较时仍需核对原题，不能把“官方/优秀论文”当作无需验证的绝对真值。

## 9. 上下文压缩与阶段交接

聊天记录不是项目记忆。每个阶段结束时更新 `reports/HANDOFF.md`，只保留继续工作所需的事实：

- 当前模式、阶段和允许/禁止的下一动作；
- 冻结合同路径与 SHA-256；
- 已验证结论 ID、最新运行清单和复现命令；
- 未决风险、失败测试和需要用户确认的决策；
- 哪些文件是权威来源，哪些已被作废。

新 Agent 必须先读 `plan.md`、`reports/PROVENANCE.md`、`reports/PROBLEM_CONTRACT.md`、`reports/DECISION_LOG.md` 和 `reports/HANDOFF.md`，再读本阶段所需文件。不得依赖上一位 Agent 没有落盘的口头假设。

## 10. 最低硬门禁

出现以下任一情况，最终验收必须 `FAIL`：

- 未冻结题意合同就进入正式求解；
- 结论改变了合同中的固定量或回答对象；
- 高影响歧义仍未解决却只给单一确定答案；
- 论文关键结论没有账本证据，或结论强度高于验证证据；
- 使用魔法搜索边界、单一起点或粗网格却声称全局最优；
- 隔离评测在封存前访问了答案来源，仍宣称独立命中；
- 合同、代码、结果或账本被修改后，没有更新清单并重跑受影响验证；
- 独立结果与封存后修正被静默合并。

这些门禁优先于排版美观、图表数量和论文措辞。
