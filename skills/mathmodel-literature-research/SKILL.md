# 数学建模文献与理论检索

本 skill 是按需启用的证据工具，不是每道题都必须进行的长篇综述。目标不是凑参考文献数量，而是在外部事实、参数口径、非平凡理论或方法选择确需依据时形成可追溯链条：**精确检索式 → 真实来源 → 可定位证据 → 变量映射 → 建模决策**。若题面附件与通用数学已足以自洽求解，应把时间优先用于建模、计算与验证，并保持 literature stage 为非必需。

启用后先选模式：

- `targeted`（竞赛默认）：围绕会改变模型或结论的少量关键缺口定向检索，设置明确时间上限；
- `full`：仅在研究型开放题、外部事实密集或用户明确要求系统综述时使用完整通道与饱和检索。

## 开始前必须读取

完整读取 `references/source-policy.md`。其来源分级、核验状态、证据强度和失败条件是本阶段的强制规范。

随后读取项目的 `plan.md`、`reports/PROBLEM_MANIFEST.json`、`PROVENANCE.md`、`HANDOFF.json` 和 `STAGE_GATES.json`，再读取 manifest 白名单中的全部题面、附件说明和数据字典。确认 intake gate 为 `PASS`，把 literature gate 标为 `RUNNING`。不要读取未授权旧代码、旧结果、范文或官方答案；不要只根据题目标题搜索，先建立问题指纹和数学原型。

严格服从任务模式和 `PROVENANCE.md` 的来源边界：

- `live-competition`：先核对当届规则是否允许联网和外部资料，记录每次外部信息事件；
- `isolated-benchmark`：能力层未授权联网时不得搜索；即使允许通用文献，也不得用比赛年份、题号、完整题名、关键专名组合成可定位本题答案的查询；
- `retrospective-audit`：封存前遵守隔离求解边界，官方答案、讲评和优秀论文只能在封存后的独立审计上下文读取；
- `guided-study`：可按用户授权比较范文，但必须把“解题答案来源”与“通用理论来源”分开登记，不能据此声称独立求解。

## 必须产出

在项目根目录创建或更新：

- `reports/LITERATURE_RESEARCH_REPORT.md`
- `references/literature_registry.csv`
- `references/search_log.csv`
- `references/claim_evidence.csv`

首次执行可复制 `assets/` 下的四个模板。不得修改 `input/`，不得把模板占位文本当成事实。

## 工作流

### 1. 建立问题指纹

从题面和附件提取：研究对象、输入与输出、时空尺度、决策变量、目标、约束、不确定性、数据规模、评价指标和每个子问题之间的依赖。把自然语言问题抽象为数学原型，例如预测、分类、评价、优化、控制、网络、排队、微分方程、博弈或多目标决策。

对歧义至少保留两个解释，先检索再定模。不要用熟悉的算法名称替代问题抽象。

### 2. 构造双语关键词矩阵

组合以下词族，并在报告中记录最终矩阵：

- 领域对象与同义词；
- 数学原型与理论名称；
- 数据结构、约束和目标；
- 算法、求解器和复杂度；
- 验证指标、基线和失败模式。

中文与英文都要覆盖；专业名词应核对标准译名。每次检索把轮次、数据库、日期、语言、精确检索式、筛选条件、实际扫描数量、纳入/排除结果、新增高价值来源及其决策影响写入 `search_log.csv`。

每次访问外部来源还要同步追加到 `reports/PROVENANCE.md`；registry 不能替代全流程来源记录。

### 3. 分层检索

`full` 模式覆盖以下六个检索通道；`targeted` 只覆盖与已登记关键缺口直接相关的通道，其余写明 N/A 理由，不按固定篇数机械达标：

1. `direct_problem`：同领域、同任务的直接研究；
2. `mathematical_analogue`：数学结构相同的跨领域研究；
3. `core_theory`：原始理论、定理、模型或权威专著；
4. `algorithm`：求解算法、收敛性、复杂度和软件实现依据；
5. `validation_benchmark`：指标、基线、消融、稳健性和评价设计；
6. `limitations`：假设失效、反例、适用边界和常见误用。

数据口径、参数或行业约束存在外部依据时，再覆盖 `data_standard`。优先使用原始论文、官方标准、官方数据和软件文档；搜索结果页、博客、百科、GitHub 与竞赛论文只能用于发现线索，不能单独支撑核心理论。

### 4. 追溯引用并判定饱和

`full` 模式对高价值来源做向后与向前追溯，并至少进行两轮增量检索；只有最后连续两轮均未新增会改变决策的高价值来源，才可声明饱和。`targeted` 模式不要求形式化饱和，但必须记录时间上限、实际查询、纳入/排除依据，以及关键缺口是否已得到足够证据；到时仍无可靠来源时应暴露不确定性，不能继续搜索挤占核心求解。

若网络、付费墙或冷门主题造成缺口，记录实际障碍、已尝试路径和影响范围。不得把没有访问到的正文写成“已核验”，不得依据摘要推导正文没有明示的公式。

### 5. 核验来源和提取证据

对每条来源分别记录：

- 身份是否核验：题名、作者/机构、年份、载体、DOI 或稳定链接；
- 内容访问级别：全文、摘要、仅元数据或不可访问；
- 来源层级、同行评审状态、证据角色和是否可引用；
- 支持的 `claim_id` 与页码、章节、定理、公式、表格或段落定位。

“来源真实”与“该来源支持当前表述”是两个不同判断。公式、定理和算法的采用必须至少有一条可访问全文的强来源及明确定位；模型记忆、搜索摘要和二手转述均不能代替核验。

### 6. 映射理论并比较候选路线

在 `claim_evidence.csv` 中把文献中的对象、符号、条件和结论映射到本题变量，明确哪些是：

- 文献已有结论；
- 本题根据数据作出的可检验假设；
- 为可计算性引入的工程近似；
- 仍需通过代码、敏感性或稳健性实验验证的内容。

至少比较两条可行建模路线。比较维度包括：结构匹配、数据要求、关键假设、可识别性、求解难度、全局/局部最优风险、验证方式、可解释性、失败模式与证据强度。不能因为某算法熟悉、容易编码或单次结果更好就直接定模。

### 7. 形成门禁结论

在报告中给出以下之一：

- `PASS`：来源身份和内容已核验；`targeted` 的全部关键缺口已关闭，或 `full` 的核心证据角色已覆盖/合理 N/A；实际采用的外部公式、理论、算法有来源和定位。只有 `full` 模式要求饱和声明。
- `CONDITIONAL`：存在真实且已记录的访问缺口，但缺口不支配核心模型；必须列出禁止据此断言的内容和后续补证动作。
- `FAIL`：核心模型或算法仍只来自搜索片段、博客或记忆；存在未核验题名/DOI；缺少证据定位、路线比较或关键检索通道。

执行校验器：

```bash
python <本 skill 路径>/scripts/validate_literature_bundle.py <项目根目录>
```

准备进入最终验收时使用：

```bash
python <本 skill 路径>/scripts/validate_literature_bundle.py <项目根目录> --paper-dir paper --strict
```

校验器只能检查记录的一致性，不能替你联网证明论文真实存在。任何身份核验仍须由实际页面、DOI、数据库元数据或原文完成。

## 阶段汇报与停止条件

完成本阶段后生成 `reports/reviews/literature.md`，至少包含：问题指纹、关键精确检索式、核心来源与证据等级、两条以上候选路线、建议采用路线、反证/失败条件、门禁状态、未决风险和可复核命令。先更新 `todo.md`、`HANDOFF.json` 和 literature gate 的产物哈希，再向用户汇报并等待确认。

`human-supervised` 下，只有用户实际查看并明确确认后，才能在 `HUMAN_REVIEW.json` 登记 literature checkpoint 为 `APPROVED`，并把 literature gate 置为 `PASS`。Agent 不得替人确认；模拟豁免只能标为 `UNVERIFIED`，不能写成比赛就绪。

门禁为 `FAIL` 时不得输出确定的最终模型。门禁为 `CONDITIONAL` 时，只有缺口不影响核心路线且已获得用户确认，才可把未决项显式带入下一阶段。
